# Тикеты и отчёты

Шаблоны для порученной работы с Linear. Если публикация не разрешена или недоступна, передай готовый текст пользователю. Не объявляй его опубликованным. Примеры команд адаптируй к текущей ветке; не запускай вслепую.

### Шаблон описания

````markdown
## Контекст
**Проверь состояние Git и безопасно синхронизируй репозиторий по `AGENTS.md`.**
Затем прочитай `AGENTS.md`, `BRIEF.md`, `PROGRESS.md` и комментарии в тикетах,
которые блокировали этот. Путь в main выбираешь сам: напрямую или через
ветку `HAC-N` (см. «Цикл тикета» в навыке).
<1–2 предложения: где этот тикет в проекте и что будет, когда он готов>

## Цель
<Одно предложение: зачем это нужно проекту>

## Что уже есть
<Файлы, функции, интерфейсы, на которые опираемся. С путями и сигнатурами.
Если ничего — «чистый лист, создаёшь с нуля»>

## Что сделать
1. <конкретный шаг>
2. <конкретный шаг>
3. ...

## Контракт
<Точные сигнатуры функций, формы данных, эндпоинты, которые этот тикет
ОБЯЗАН выставить или использовать. Дословно из BRIEF.md. Копируется в код как есть.
Если тикет не на стыке лейнов — «нет»>

## Готово когда
- [ ] <проверяемый пункт, не «работает»>
- [ ] <проверяемый пункт>
- [ ] `make check` зелёный
- [ ] запушено в main
- [ ] отчёт написан комментарием в тикете

## Мини-тест
```bash
<команда или последовательность, которая должна пройти>
```
Ожидаемый результат: <что именно увидим — строка, файл, код ответа>

## Файлы
Создать: <список>
Изменить: <список>
Не трогать: <файлы чужих потоков>

## Не делать
- <что агент захочет сделать, но не должен>
- <соседняя проблема, которую заметит и полезет чинить>

## Связи
Блокируется: <HAC-N или «ничем»>
Блокирует: <HAC-M или «ничего»>

## Сдача
1. Код в main — через ветку или напрямую, на усмотрение исполнителя:
```bash
git commit -m "[HAC-N] <что сделано>"
# При чистом дереве и готовой ветке HAC-N:
git checkout main
git pull --ff-only
git merge HAC-N
# Проверить интеграцию перед push
git push
```
2. **Комментарий в этом тикете по форме отчёта ниже** —
   что сделано, что теперь можно звать, отклонения, файлы, проверка.
   Без комментария тикет не закрыт.
3. Статус → Done

Оценка: <N> мин
````

```markdown
## Отклонения от тикета

<если менялся КОНТРАКТ — написать это первой строкой и капслоком>

## Файлы
Создано: <пути>
Изменено: <пути>

## Проверка

<если всё — «ничего»>

```

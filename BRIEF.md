# Бриф: AI Sana Challenge Hub — от бизнес-задачи к решению

Трек 07 «Образование» · Кейс 01 (владелец: МНВО — AI Sana) · Команда TayMas Systems · 13:00–18:00

Текст кейса дословно: `HackAlem_AI_кейс_по_геймификации_практических_заданий.pdf` (RU — стр. 1–5).

## Проблема

Бизнес описывает задачу для студентов слишком коротко, и командам непонятно, за что браться.
MVP помогает представителю бизнеса превратить черновик в полноценную карточку: задаёт уточняющие
вопросы, считает рейтинг готовности (0–100) с расшифровкой и публикует карточку в открытом каталоге.
Студенческие команды сами откликаются, бизнес вручную выбирает, с кем работать.

## Мастхэв из кейса (цитаты)

Сквозной сценарий (раздел 2): «Черновик → Уточнение → Карточка → Рейтинг → Каталог → Выбор студентов → Выбор бизнеса».

- [ ] **Конструктор задачи**: «Свободный ввод; проверка полноты; минимум 3 уточняющих вопроса; редактируемая карточка; ручное подтверждение»
- [ ] **Карточка задачи**: «Название, контекст, потребность, пользователи, данные, ограничения, ожидаемый результат, критерии успеха, контакт и формат взаимодействия»
- [ ] **Рейтинг задачи**: «Оценка от 0 до 100; расшифровка начисленных баллов; список недостающих сведений; пересчёт после редактирования»
- [ ] **Общий каталог**: «Все опубликованные задачи доступны всем командам; сортировка по рейтингу; фильтры по теме и уровню готовности»
- [ ] **Отклики команд**: «Любая команда может отправить идею решения, план и ссылку на прототип. Число откликов не ограничивается»
- [ ] **Выбор бизнеса**: «Список предложений и ручные действия выбрать или отклонить. Автоматическое назначение команды запрещено»
- [ ] **AI-функция**: «минимум одна содержательная AI функция … анализ полноты описания и генерация уточняющих вопросов либо преобразование ответов в карточку». «Если внешний API недоступен, допускается локальная заглушка, однако команда должна показать промпт, формат входа и выхода и обработку некорректного ответа»
- [ ] Ограничения ИИ: «ИИ не должен добавлять факты, которых не сообщил пользователь» · «Сформированный текст редактируется и подтверждается человеком до публикации» · «ИИ не выбирает команду за бизнес»
- [ ] **Шкала рейтинга** (раздел 4): Контекст и потребность 20 · Данные и материалы 20 · Ожидаемый результат 15 · Критерии успеха 15 · Ограничения 10 · Пользователи 10 · Связь с бизнесом 10. «Баллы начисляются только за заполненные и подтверждённые поля»
- [ ] **Уровни готовности**: 0–39 черновик (видна, «требует уточнения») · 40–69 рабочая · 70–89 готовая (выше в каталоге) · 90–100 приоритетная (выделяется). «Низкий рейтинг не скрывает задачу и не запрещает отклик»
- [ ] **Исходные данные** (раздел 6, синтетика): 5 черновиков · 5 карточек со всеми полями и баллом · 5 профилей команд (название, интересы, навыки, технологии) · 5 откликов (команда, идея, план, срок, ссылка)
- [ ] **Сдача** (раздел 10): «README с архитектурой, формулой рейтинга задачи, правилами каталога и тестовыми сценариями» · «Демонстрация до 5 минут на одном заранее подготовленном примере»
- [ ] **Обязательная демонстрация** (раздел 11): слабое описание → дополнение → рост рейтинга → публикация → отклик команды → бизнес вручную принимает/отклоняет. «Все переходы должны работать в MVP, а не на слайдах»

Не требуется (раздел 7): регистрация и роли, чат/уведомления/файлы, своя ML-модель и векторная БД, мобильная адаптация, полный трекер (шаг 8 «Результат» — баллы команде за прогресс — делаем только если останется время).

## Мастхэв из критериев оценки

- [ ] Сквозной сценарий работает целиком: черновик → публикация → отклик → решение бизнеса (20 баллов по кейсу)
- [ ] Рейтинг прозрачен, пересчитывается, влияет на позицию в каталоге (25 баллов по кейсу — самый дорогой критерий)
- [ ] README по списку организатора; проект запускается в чистом окружении (Docker + без Docker)
- [ ] `make check` — автоматическая проверка основного сценария
- [ ] Не падает на корректных данных; пустой/мусорный ввод обрабатывается понятным сообщением

## Что на выходе

Представитель бизнеса вводит короткий черновик задачи, отвечает минимум на три уточняющих вопроса,
правит собранную карточку и видит, как рейтинг растёт с «черновика» до «готовой»; после публикации
любая студенческая команда находит задачу в каталоге и отправляет отклик, а бизнес вручную принимает
или отклоняет его — всё в одном веб-приложении на `http://localhost:8000`.

## Контракт между потоками

Модели — `app/models.py` (уже в main, читать оттуда). Ключевые сигнатуры:

```python
# app/models.py
CARD_FIELDS = ["title", "context", "need", "users", "data", "constraints",
               "expected_result", "success_criteria", "contact", "interaction_format"]
INDUSTRIES = ["Образование", "Финансы", "Ритейл", "Логистика", "Медицина", "Госуслуги", "Промышленность", "Другое"]
Level = Literal["draft", "workable", "ready", "priority"]      # LEVEL_LABELS — русские названия

class Question(BaseModel):  field: str; question: str; why: str
class Answer(BaseModel):    field: str; question: str; answer: str
class CardFields(BaseModel): title, context, need, users, data, constraints,
                             expected_result, success_criteria, contact, interaction_format  # все str, default ""
class Card(CardFields):     id, draft_id, industry, status: "draft"|"published", confirmed: bool,
                            score: int, level: Level, answers: list[Answer], created_at, published_at
class RatingItem(BaseModel): key, label, weight, awarded, hint
class Rating(BaseModel):    score: int; level: Level; level_label: str; items: list[RatingItem]; missing: list[str]
class Team(BaseModel):      id, name, interests: list[str], skills: list[str], technologies: list[str]
class Proposal(BaseModel):  id, card_id, team_id, idea, plan, deadline, link,
                            status: "pending"|"accepted"|"rejected", created_at, decided_at

# app/rating.py  (ядро)
def compute_rating(card: CardFields) -> Rating: ...
def level_for(score: int) -> Level: ...

# app/ai.py  (ядро) — всё через app/llm.py; без ключа работает локальная заглушка
def generate_questions(draft_text: str, industry: str) -> list[Question]: ...   # len >= 3
def build_card(draft_text: str, industry: str, answers: list[Answer]) -> CardFields: ...
def ai_mode() -> str: ...   # "openai" | "nvidia" | "stub" — для показа в интерфейсе

# app/llm.py  (ядро)
class LLMClient:
    def complete(self, messages: list[dict[str, str]], *, json_schema: type[BaseModel] | None = None,
                 temperature: float = 0.2) -> str | BaseModel: ...
def get_client() -> LLMClient: ...
def llm_available() -> bool: ...

# app/store.py  (обвязка) — get_store() синглтон, JSON-файл, сид из data/seed.json
add_draft(text, industry) -> Draft · get_draft(id) · add_card(card) · get_card(id) · update_card(card)
list_cards(*, published_only=True, industry=None, level=None) -> list[Card]   # по score убыв., затем по дате
list_teams() · get_team(id) · add_proposal(p) · get_proposal(id) · update_proposal(p) · list_proposals(card_id)
```

Маршруты веба (поверхность), по ним пишутся смоук-тесты:

| Метод и путь | Что делает |
| --- | --- |
| `GET /` | Вход: «Разместить задачу» и «Каталог задач» |
| `GET /business/new` · `POST /business/new` (text, industry) | Черновик → `generate_questions` → страница вопросов |
| `POST /business/drafts/{id}/answers` (answer_0..n) | `build_card` → карточка сохраняется → redirect на редактор |
| `GET /business/cards/{id}/edit` · `POST /business/cards/{id}/edit` | Редактируемая карточка + панель рейтинга; сохранение = пересчёт |
| `POST /business/cards/{id}/publish` (confirmed=on) | Подтверждение и публикация |
| `GET /catalog?industry=&level=` | Все опубликованные, сортировка по рейтингу, фильтры |
| `GET /tasks/{id}` | Карточка, рейтинг, отклики, форма отклика (team_id, idea, plan, deadline, link), кнопки бизнеса |
| `POST /tasks/{id}/proposals` | Новый отклик, статус pending |
| `POST /proposals/{id}/decision` (decision=accept/reject) | Ручное решение бизнеса |
| `GET /health` | `{"status":"ok","ai_mode":...}` |

## Стек

Python 3.12 · FastAPI + Jinja2 (серверный HTML, без Node-сборки) · JSON-хранилище в `data/` · OpenAI SDK.
Один процесс, один порт, одна команда запуска — минимум точек отказа при воспроизведении у эксперта.

## Провайдеры

| Задача | Провайдер |
| --- | --- |
| Уточняющие вопросы, сборка карточки (structured output) | OpenAI через `app/llm.py` |
| Резерв при недоступности OpenAI | NVIDIA, переключение `LLM_PROVIDER=nvidia` в `.env` |
| Нет ключа вообще | Локальная заглушка в `app/ai.py`: детерминированные вопросы по пробелам рейтинга, карточка из ответов |
| Рейтинг | Без LLM — детерминированные правила, чтобы был прозрачным и тестируемым |

## Главный риск

Веб-слой самый большой и лежит на демо-пути целиком; если конструктор не собирается к 15:30 — режем
редактор до простой формы без панели подсказок и живого пересчёта, но сохраняем все семь переходов.
